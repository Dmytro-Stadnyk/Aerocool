## 3. Найденные Дефекты До Исправления

### P1. Указатели Вели На Старый Полный Аудит `91`

`README.md`, `AGENTS.md` и `docs/01-documentation-map.md` называли аудит `91` последним полным аудитом документации. После этого появились:

- профильный UX/UI-аудит `92`;
- профильный tooling-аудит `93`;
- фактический переход проекта на `Hugo 0.164.0`.

Для запроса “на текущий момент” это уже недостаточно: новичок должен видеть свежий полный snapshot после `93`.

Исправление:

- создан текущий полный аудит `94`;
- `README.md`, `AGENTS.md` и `docs/01-documentation-map.md` переключены на `94`;
- аудит `91` помечен как исторический snapshot;
- карта документации обновлена до диапазона `01-94` и `97` физических файлов внутри `docs/`.

### P2. Карта Документации Имела Старую Дату И Диапазон

`docs/01-documentation-map.md` была датирована 2026-06-28 и описывала диапазон `01-93`. После добавления текущего полного аудита это стало устаревшим.

Исправление: дата карты обновлена до 2026-07-07, диапазон изменен на `01-94`.

### P3. Описание `script_check.sh` В README Было Слишком Широким

README говорил, что `script_check.sh` проверяет `.DS_Store`, но сам скрипт фактически проверяет `.DS_Store` только в `static/` и `public/`.

Исправление: формулировка уточнена как `.DS_Store` в `static/` и `public/`.

## 6. Сверка С Лучшими Практиками 2026

Документация согласована с актуальными практиками:

- официальный Hugo-документ `css.TailwindCSS` подтверждает, что функция обрабатывает CSS через Tailwind CSS CLI, а начиная с Hugo `0.161.0` standalone Tailwind binary не поддерживается; значит, текущий стандарт “держать `tailwindcss` и `@tailwindcss/cli` в npm-зависимостях проекта” верен для `Hugo 0.164.0`;
- релиз Hugo `0.164.0` опубликован как актуальный release на дату проверки; локальный project pin совпадает с upstream tag `v0.164.0`;
- Google Article structured data требует, чтобы изображения были доступны для обхода, представляли размеченный контент, имели поддерживаемый формат и для лучшего результата покрывали соотношения **16:9**, **4:3**, **1:1** с минимумом **50K** пикселей; это зафиксировано в документах `05`, `06`, `67`, `79`, `89`;
- Google Image SEO требует содержательные изображения, описательные `alt`, корректные HTML-элементы изображений и доступность URL для сканирования; локальный `seo-image`, `cover`-контракт и image playbook этому соответствуют;
- web.dev фиксирует текущие Core Web Vitals как `LCP`, `INP`, `CLS` с ориентирами `2.5s`, `200ms`, `0.1` на p75; это закрывают документы `12`, `13`, `14`, `83`;
- Google guidance по AI-generated content делает акцент на точности, качестве, релевантности, metadata, alt и structured data validation; локальные документы `24`, `25`, `26`, `79`, `85`, `88` не обещают “магическую AI-видимость”, а усиливают сущности, факты, видимый текст и проверяемую разметку.

## 10. Что Не Удалялось

Legacy-аудиты не удалялись. Причина: они являются audit trail проекта и часто нужны, чтобы понять, почему была принята конкретная SEO/schema/tooling-логика.

Без отдельного подтверждения нельзя удалять:

- исторические audit-файлы `29-93`;
- документы с прошлым target-стеком, если они явно помечены как исторические;
- `.DS_Store` в `content/`, потому что текущая задача была документационной, а не cleanup-задачей.

Что можно удалить или архивировать только после отдельного решения:

- исторические аудиты, если будет выбран отдельный архивный формат;
- `.DS_Store` в `content/`;
- устаревшие скрипты или поля, если они больше не используются и это подтверждено поиском по проекту.
