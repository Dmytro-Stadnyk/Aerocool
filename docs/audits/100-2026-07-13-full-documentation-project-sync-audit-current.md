## 3. Исправленные дефекты

### 3.1. Система отзывов

README ошибочно утверждал, что `netlify/functions/reviews.mjs` читает approved-записи. Исправленный контракт:

- функция принимает только `POST`;
- валидирует запрос и создает только `pending`-отзыв;
- другие методы получают `405 Method Not Allowed` и `Allow: POST`;
- approved-записи читает `scripts/export_reviews.mjs` перед сборкой;
- публичные `GET` и административные маршруты не реализованы и теперь явно помечены как возможное будущее развитие.

Из контентного чек-листа удалены формулировки о «будущей системе» и «переключении на approved-отзывы»: этот слой уже работает.

### 3.2. Товарная галерея

Прежний совет «дать файлу понятное имя» был недостаточно точным. Документация теперь фиксирует фактический контракт `gallery-image-meta.html`:

- первый кадр задает `image`, обычно `01-front.webp`;
- дополнительные кадры должны использовать одно из разрешенных смысловых имен;
- опубликованный формат текущего проекта — WebP;
- неизвестное имя обрабатываемого растрового ресурса останавливает сборку;
- SVG не является обрабатываемым Hugo ресурсом и автоматически в товарную галерею не входит;
- `10-dimensions.svg` допустим только как отдельная встроенная схема вне галереи, а для галереи используется `10-dimensions.webp`.

Контракт синхронизирован в README, AGENTS и документах `03`, `05`, `06`, `07`, `10`, `21`, `34`, `37`.

### 3.3. Материал товара в schema.org

Документация теперь описывает фактическое сопоставление:

1. Главная товарная сущность находится по `about_entities`.
2. Ее поле `material` ссылается на сущность материала.
3. Сущность должна иметь статус `confirmed`.
4. Шаблон берет локализованное название и выводит `Product.material`.
5. Произвольное дублирующее поле материала во front matter не добавляется.

После production-сборки `Product.material` найден во всех `24` языковых товарных страницах: по `8` значений `Mesh`, `Loft Air` и `Racer`.

### 3.4. Архивы исходников производителя

Постоянные документы теперь знают обо всех четырех непубличных Git-архивах:

| `docs/SKY LITE/` | `14` | около `65 MiB` | `7 PNG`, `7 WebP` |

## 12. WebMCP и AI-агенты

Документация дополнена рекомендациями Chrome по оценке инструментов:

- обычные HTML-формы проверяются детерминированно и независимо от AI;
- агентные сценарии проверяют выбор правильного инструмента, параметры и завершение задачи;
- контакт и отзыв сохраняют явное подтверждение пользователя;
- недоверенное внешнее или пользовательское содержимое не должно становиться скрытой инструкцией для агента;
- Lighthouse/PageSpeed проверяет техническую доступность, но не доказывает правильный выбор инструмента во всех сценариях.

Автоматизированного набора WebMCP-сценариев в репозитории пока нет. До его появления [production gate](../quality/14-production-quality-gate-2026.md) требует ручной протокол.

## 14. Оставшиеся действия вне документационного слоя

1. Обновить Node.js 24 до актуального исправляющего выпуска отдельной задачей и синхронно изменить `mise.toml` и `netlify.toml`.
2. Отдельно проверить Tailwind `4.3.2` и `@netlify/database` `1.1.0`, не смешивая обновление зависимостей с документационным аудитом.
3. Пройти production gate и только затем переключить индексируемые страницы на `index,follow`.
4. Перенести исправленные cache headers в production и повторить живую проверку стабильных и fingerprinted URL.
5. Подтвердить `REVIEW_EMAIL_HASH_SALT`, credits, лимиты и стоимость Netlify Database в Dashboard.
6. Заменить временную общую группу отзывов `all` полноценной языковой моделью до production SEO-режима.
7. Создать автоматизированный набор WebMCP-сценариев или продолжать фиксировать ручной протокол перед каждым релизом форм.
8. Рассмотреть Git LFS или отдельное хранилище, если архивы производителя продолжат заметно увеличивать `.git`.

Эти пункты не являются скрытыми дефектами документации: каждый из них теперь явно описан в действующих руководствах и имеет проверяемое условие завершения.
