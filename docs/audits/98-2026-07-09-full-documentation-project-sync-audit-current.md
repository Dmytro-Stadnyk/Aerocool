### P1. Старый Аудит Фиксировал Устаревший Риск По Товарным PNG

Аудит `97` фиксировал, что часть главных товарных PNG повторяет один файл. На текущий момент это уже не соответствует репозиторию.

Фактическое состояние:

- повторов по SHA-256 хешу среди `01-front.*` нет;

Исправление: текущий аудит `98` закрывает старый риск по повторяющимся товарным PNG и фиксирует новый фактический image baseline.

### P2. В `docs/` Есть Ненумерованный Архив Исходников

`docs/XTAL/` содержит исходные изображения производителя: **47** файлов JPG/JPEG, примерно **127 МБ**. Эта папка не является документацией для чтения.

Исправление:

- папка остается ненумерованным архивом исходников;
- она исключается из маршрута чтения `01-98`;
- правило использования остается прежним: брать оттуда исходники и готовить оптимизированные WebP/JPEG внутри `content/`, а не публиковать исходники как Hugo-ресурсы.

## 6. Сверка С Лучшими Практиками 2026

Документация согласована с актуальными практиками:

- официальный Hugo-документ `css.TailwindCSS` подтверждает, что функция обрабатывает CSS через Tailwind CSS CLI, а начиная с Hugo `0.161.0` standalone Tailwind binary не поддерживается; значит, текущий стандарт “держать `tailwindcss` и `@tailwindcss/cli` в npm-зависимостях проекта” верен для `Hugo 0.164.0`;
- Google Article structured data показывает image-массив для **1:1**, **4:3** и **16:9** изображений; локальный `image` + `cover`-контракт и crop-наборы статей/новостей этому соответствуют;
- Google Image SEO требует содержательные изображения, описательные `alt`, корректные HTML-элементы изображений и доступность URL для сканирования; локальный `seo-image`, `cover`-контракт и image playbook этому соответствуют;
- Chrome WebMCP описан как proposed web standard и progressive enhancement для AI-агентов; документация проекта корректно держит его как экспериментальный слой, а не как замену schema.org, accessibility, sitemap или видимого контента;
- Chrome WebMCP Declarative API поддерживает аннотации HTML-форм; проект применяет их к контактной форме, форме отзывов и фильтрам каталога;
- `llms.txt` используется как краткая Markdown-карта для AI/LLM-агентов; документация проекта не превращает его во второй sitemap и не хранит там товарные цены, наличие или merchant facts;
- web.dev фиксирует текущие Core Web Vitals как `LCP`, `INP`, `CLS`; локальные документы `12`, `13`, `14` и аудит `83` покрывают этот контур;
- подход к исходникам производителя корректный: `docs/XTAL/` остается внутренним архивом, а публичный сайт использует оптимизированные WebP в `content/`.
